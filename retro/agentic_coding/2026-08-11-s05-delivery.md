# S05 — Delivery

### The task description described a design the client had already abandoned

**Cycle:** Wave S / S05
**Cost:** ~30 min of design work that would have been thrown away
**Category:** wrong-assumption

**Symptom.** S05's task entry, and the design doc's `ios_backend_service.md` "Delivery" section,
both describe the report as a directory with four sibling roots — `report/`, `thumbs/`,
`previews/`, `.cache/video/` — that has to ship together in one bundle because per-file signed
URLs would break every relative link. That is I24's shape, and it is real: `render_report`'s
default output is exactly those four roots with plain relative paths. Building against it would
have produced a working bundle, a full test suite, and a design nobody's client actually uses.

**Root cause.** I25 (`AssetSchemeHandler.swift`), which landed *the same day* as I24 and is what
`ReportLoader` actually wires up (`assetScheme: AssetSchemeHandler? = .init()` is not optional),
renders the report with `media_rel="storyasset://"` instead. Its own doc comment says the
downloaded bundle "carries no `thumbs/` or `previews/` directory at all" — the opposite of I24's
premise, and the newer decision. The task description for S05 was written against I24's shape and
never updated once I25 shipped, so it was quietly describing a design one commit out of date.
Nothing in the tracker's Wave S table or the task entry flagged the contradiction; it only showed
up from reading `AssetSchemeHandler.swift` itself, which the task's own reading list *did* require
("read these to understand what the client already expects to receive") — the instruction was
right, the description above it was stale.

**Fix.** Built the I25 shape: a bundle with no media in it, and a generic
`GET /trips/{trip_id}/media/{relpath}` that serves whatever `trip.json` names, regardless of
which directory convention the path uses. This sidesteps the question of whether posters "should"
live outside `.cache/` (Q12 asked whether to move them on the Python side) — the answer stopped
mattering once delivery serves by relative path instead of by directory allowlist.

**Second finding, same root cause.** Building the I25 shape and then checking it line-by-line
against `AssetSchemeHandler.swift` surfaced that `AssetRequestParsing.parse` only recognises
`thumbs` and `previews` as hosts. A video poster's path, `.cache/video/<hash>_poster.jpg`, becomes
`storyasset://.cache/video/<hash>_poster.jpg` under the prefix — host `.cache` — which the parser
rejects. This is a live bug in the client, not a hypothetical: today's app would fail every video
poster with `unrecognizedRequest`. It surfaced only because two files that describe the same
contract (`export/report.py`'s path conventions and `AssetSchemeHandler.swift`'s parser) were
read side by side rather than each trusted in isolation. Logged as open question 21 rather than
fixed, since fixing it means editing `ios/**`, which S05 does not own.

**Lesson.** When two design docs (or a design doc and the code) disagree about a contract you're
about to build against, the code that actually runs wins — but "actually runs" has to be checked
against the *newest* code, not the first file that describes the shape. Reading order matters: the
task's own reading list put the Swift client files last, after the design docs; reading them
first would have caught the stale premise before drafting anything. **When a task description
cites which file to read for ground truth, read that file before accepting the description's own
framing of the problem**, not after.
