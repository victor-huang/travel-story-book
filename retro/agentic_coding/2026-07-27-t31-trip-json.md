# T31 `trip.json`, and a whole class of unstable identifiers (2026-07-27)

The canonical intermediate artifact. One test caught a defect that would have reached both
outputs, and one failure was the environment rather than the code.

---

### Every database rowid published in the artifact churned between builds

**Category:** design-flaw
**Cost:** caught by a test written on a hunch, before either consumer existed

**Symptom.** `test_rerunning_produces_an_identical_document` — a build, then a second build with
no input change — failed on `event_id: 1` becoming `event_id: 2`. Fixing that surfaced
`scope_id`, and fixing *that* surfaced the cluster id.

**Root cause.** `day`, `event` and `cluster` rows are deleted and re-inserted on every run, by
design: their identity is their position in a media set that is recomputed each time. So their
`AUTOINCREMENT` ids climb on every build. Publishing them made `trip.json` differ from itself for
a library that had not changed by one byte.

Three symptoms, one cause, and I fixed them one at a time until the pattern was obvious. The
project already *knew* this — `overrides.toml` addresses everything by filename precisely because
event and cluster ids are reassigned, and I had written that reasoning down eight hours earlier.
I did not carry it across to the artifact.

**Fix.** No rowid is published. An event is `<date>#<seq>`, a cluster is its keeper's `asset_id`,
a selection carries rank and reason with no scope id because the asset already names its day and
event. Two builds of the real 286-item trip are now byte-identical.

**Lesson.** **"This identifier is not stable" is a property of the identifier, not of the one
place you noticed it.** Having established that rowids are unstable for overrides, the next step
should have been to ask where *else* they escape — which is the same "sweep the class" lesson from
the read-and-write-the-same-field bug, hit again from a different angle. The generalisation that
finally worked is a rule, not a fix: *nothing derived from insertion order leaves the database.*

Worth noting what caught it: not a review, but a test asserting a property I could not have
checked by reading the output once. Rendering the document looked perfect both times.

### `uv sync` silently pruned the optional extras

**Category:** environment
**Cost:** twelve failing tests that had nothing to do with the change

**Symptom.** After adding `jsonschema` to the dev group and running `uv sync`, the whole
`test_quality.py` suite failed. The diff touched none of it.

**Root cause.** `uv sync` without `--extra` *removes* extras that are not requested. `opencv` and
`torch` went away, so every image-scoring test lost its dependency. `CLAUDE.md` documents
`--extra vision/video/exif` for the initial install and I ran the bare form out of habit.

**Fix.** Re-synced with the extras. Nothing in the codebase was wrong.

**Lesson.** When a test failure is *distant* from the change, suspect the environment before the
code. The tell was that the failures were entirely in one unrelated module — a real regression
from a `trip.json` change could not have reached Laplacian variance. That is the second time this
week the right first question was "is the test wrong, or is the world?" rather than "what did I
break?".

### Deciding where the schema lives, and who validates against it

**Category:** design — recorded because the reasoning is easy to lose

`jsonschema` went in as a **dev** dependency, not a runtime one, and the pipeline does not
validate its own output. The schema is the artifact's published contract for T40, T41 and any
Phase 2 reader; the code that writes the file should not also be the authority on whether the file
is acceptable. Tests validate; the pipeline just writes.

The schema also carries the *reasoning* in `description` fields — why `no_speech` and
`not_processed` are distinct, why `event_id` is not a rowid, why there is no aesthetic score.
A consumer reads the schema, not this repo's retros.

---

## Encoded as project rules

- Nothing derived from insertion order leaves the database. Published ids are functions of the
  media set: content-hash prefix, `<date>#<seq>`, keeper `asset_id`.
- `trip.json` is byte-identical across builds of an unchanged library, asserted by a test.
- Absent data is `null` beside a status field, never an omitted key — `transcript_status`,
  `privacy.home_configured`, `context.supplied`.
- No aesthetic or composition score appears in the artifact, and a test asserts their absence:
  they are Phase 2, and a plausible invention is worse than a gap.
- Install with the extras (`uv sync --extra vision --extra video --extra exif --extra geo`);
  a bare `uv sync` prunes them.
